# Contributing Guidelines

[简体中文](CONTRIBUTING.md) | **English**

Thank you for contributing to **WatchSend**! This project follows a lightweight but strict source code management standard: **Conventional Commits + SemVer 2.0.0 + CHANGELOG**.

> **About the Origin**: WatchSend is the watch-exclusive branch of [OldSend](https://github.com/styisme/oldsend). The underlying protocol stack (LocalSend compatibility, cross-network transfer) is inherited from OldSend, while the UI layer has been completely rewritten for Wear OS. Related Docs: [README](README_EN.md) | [CHANGELOG](CHANGELOG.md) | [AI Disclosure](docs/AI_DISCLOSURE.md) | [Dev Constraints](docs/DEVELOPMENT_CONSTRAINTS.md).

---

## ⚠️ About AI-Generated Code

Following the [AI Development Guidelines](https://github.com/styisme/ai-development-guidelines), the vast majority of code in this project is **AI-assisted** (especially the Wear OS-exclusive 3D wheel algorithm, predictive back animations, pure Java dynamic pill card layouts, and hardware compatibility wrappers).

When submitting a PR, you must:
- State whether the changes were generated by AI.
- **Manually verify the functionality** (must be run on a real watch or emulator, not just compiled successfully).
- If you also used AI, please specify the model and prompt direction in the PR description.

## Local Development

### Requirements

| Component | Version |
|---|---|
| JDK | 8 (Must use JDK 8 to ensure legacy Android 2.3 compilation) |
| Gradle | 5.6.4 |
| Android SDK | compileSdk 30, buildTools 30.0.3 |

### Build Commands

We provide a Python-based one-click build script with interactive signing injection and auto-Gradle download:
```bash
git clone https://github.com/styisme/watchsend.git
cd watchsend
python sync_version.py   # Automatically sync version from CHANGELOG
python build.py          # Use one-click build script (supports auto-signing)
```

### Cloud Build & Auto Release
The project is equipped with a powerful GitHub Actions auto-release pipeline:
- Triggered automatically when `CHANGELOG.md` changes and is pushed to `main` or `master`.
- CI automatically extracts version -> injects into Gradle -> decrypts signing keys -> compiles Release APK -> automatically tags and publishes to GitHub Release.

## Commit Convention

Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

```
<type>(<scope>): <subject>
```

### Allowed Types
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes only
- `style`: Formatting changes (no logic change, e.g., UI adjustments)
- `refactor`: Refactoring
- `perf`: Performance optimization
- `build`: Build system changes
- `ci`: CI configuration changes
- `chore`: Chores (version bump, .gitignore)

### Common Scopes
- `ui`: UI, style-related
- `watch`: Watch-exclusive logic (round screen adaptation, wheel effects, crown interaction)
- `lang`: Multi-language related
- `core`: Core transfer logic
- `http`: HTTP server/client
- `discovery`: Multicast & device discovery
- `transfer`: File sending/receiving
- `web`: WebShare frontend related

### Examples
```
feat(watch): add rotary encoder list scrolling support
fix(ui): resolve bright yellow progress bar background in dark mode
ci: integrate fully automatic signing and release pipeline
```

## Pull Request Process

1. Fork the repo (or edit directly)
2. Create a branch: `git checkout -b feat/your-feature`
3. Modify code and verify locally / via Actions
4. Use Conventional Commits for commits
5. Push and open a PR
6. Wait for CI to pass + Review

### PR Description Should Include

```markdown
## Changes
Briefly describe what was done

## Change Type
- [ ] feat / fix / refactor / docs / chore

## Related Issue
Closes #123

## Testing Method
- [ ] Local build passed
- [ ] Tested on real watch (please specify watch model & Wear OS version)
- [ ] Actions build passed

## AI Generated?
- [ ] Yes (please specify model and manual verification content)
- [ ] No
```

## Versioning Rules (Strict Automation)

Follow [Semantic Versioning 2.0.0](https://semver.org/):

| Change | Version Bump |
|---|---|
| Incompatible changes | **MAJOR** |
| Backwards-compatible features | **MINOR** |
| Bug fixes | **PATCH** |

⚠️ **IMPORTANT**: This project has automated version synchronization. **NEVER manually edit `versionCode` or `versionName` in `app/build.gradle`**.
Simply add a new version in `CHANGELOG.md` (e.g., `## [1.4.0] - 2026-11-07`), and CI will inject it automatically before building.

## Troubleshooting

**Q: Build error `tools.jar` missing?**
A: You must use JDK 8. GitHub Actions is fixed to Zulu JDK 8.

**Q: Build error `error: duplicate attribute`?**
A: There are duplicate `android:id` or attributes in layout files (e.g., `activity_main.xml`). Check if they were overwritten during regex batch replacements.

**Q: Sender reports `Cleartext HTTP traffic not permitted`?**
A: Android 9.0+ blocks cleartext HTTP by default. Ensure the `<application>` tag in `AndroidManifest.xml` contains `android:usesCleartextTraffic="true"`.

**Q: After enabling dark mode, some pages still have white-on-white text / harsh colors?**
A: All UI in WatchSend is dynamically generated in pure Java. Check the `onCreate` method of the corresponding page to ensure it calls `WatchUiUtils.getPillBackground(this)` and text colors use dynamic assignment like `isDark ? 0xFFE0E0E0 : 0xFF1C1B1F`.

**Q: UI scaling has no effect after adjustment?**
A: Starting from v1.4.0, because Android 11+ intercepts `updateConfiguration`, the scaling logic has been migrated to `createConfigurationContext` within `attachBaseContext`. Please ensure all Activities override `attachBaseContext` and call `WatchUiUtils.wrapScale(newBase)`.

**Q: Why can't I get Material You dynamic colors on Android 12+?**
A: Ensure the theme in `AndroidManifest.xml` is not a hardcoded `Theme.Light`, but set to `@android:style/Theme.DeviceDefault.NoActionBar`, and `targetSdkVersion` is not too low (currently 30) so the system can provide dynamic color palettes.

**Q: How to find missing i18n keys?**
A: In Settings -> Language list, scroll to the bottom and select `debug_keys`. The UI will directly display the raw keys instead of translated text, making it extremely fast to locate missing translations or layout overflow issues.

**Q: Swipe back gesture conflicts with system back / freezes?**
A: Check if the "Block System Back" switch is enabled in Settings. Internally, we intercept native back via `onBackPressed()` and delegate everything to `WatchUiUtils.handleSwipeBack()`.

**Q: After enabling round screen optimization, the top title bar disappears, how to go back?**
A: This is intentional for an immersive experience. When round screen optimization is on, it relies on **swiping to go back**. If swiping fails, check if the `handleSwipeBack` event in `WatchUiUtils` is being over-consumed by internal controls on the current page (like a horizontal ScrollView).

**Q: Why is the APK built by auto-release signed with a Debug key?**
A: Check if the 4 signing parameters (`NAS_KEYSTORE_BASE64`, `NAS_KEYSTORE_PASSWORD`, etc.) are correctly configured in the repository's `Settings -> Secrets and variables -> Actions`. If not configured, CI will print a warning and fall back to Debug signing.

**Q: Older watches (Wear OS 2.0 or below Android 7.0) find the Tile feature non-functional after installing the new version?**
A: Quick Settings Tiles (`QuickScanTileService`) and rotary events (API 26+) require system-level support. The code includes API version compatibility checks; lower-version devices will automatically ignore these features, without affecting basic transfer functionality.

**Q: Why does Shizuku silent installation fail in Geek Mode?**
A: Because the project strictly avoids third-party dependencies, it uses a hand-written Binder IPC proxy. Ensure Shizuku is running on your device and has authorized WatchSend in its internal permission manager. If the ROM is non-standard, the system may intercept it and fall back to the standard installation dialog.

**Q: WebShare (Web UI) fails to load or shows a blank screen?**
A: The web frontend is completely isolated in `app/src/main/assets/index.html`, featuring built-in 10-language dictionaries and full API routes. Ensure that all routes like `/web/info` and `/web/files` are registered in `OldSendService`. If you modified the frontend during development, clear your browser cache and try again.
