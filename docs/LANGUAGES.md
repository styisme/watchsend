# WatchSend 多语言使用指南

本文说明 WatchSend 的语言覆盖范围、如何切换语言、界面文案的回退规则，以及新增一种语言或一条文案时该改哪里。

> 一句话版本：**App 端支持 52 种语言，10 个基础语种各 357–358 条、其余 42 个语种各 353 条，合计 18,403 条；网页端（WebShare）只支持 10 种语言。两者覆盖面不同，不是同一个数字。**

---

## 一、两套语言体系，别混在一起

| 位置 | 语言数 | 词条量 | 实现方式 | 切换方式 |
| --- | --- | --- | --- | --- |
| App 界面（手表端） | 52 | 353–358 条/种，合计 18,403 | `I18nManager`（Java 词条表，按需加载） | 设置 → 语言，或跟随系统 |
| 网页端（WebShare） | 10 | 约 30 条 | `assets/index.html` 内的 JS 字典 | 自动识别浏览器语言，页面内可下拉切换 |

网页端只做 10 种（zh / zh_TW / en / ja / ko / de / fr / es / ru / pt），因为它是浏览器里的临时页面、词条量小；App 端才是 52 种全量。旧版 README 曾把两者写成同一个数字，已在 1.7.12 的文档审查中修正。

---

## 二、切换语言

1. 打开 **设置 → 语言 (Language)**。
2. 选择「跟随系统」时，按系统语言自动匹配：`zh` 会区分简繁（TW / HK → 繁体），`iw → he`、`in → id`、`tl → fil`、`no → nb` 这类历史代码会被归一化。
3. 选中具体语言后，App 各页面会重建并立即生效，不需要重启进程。
4. 语言列表最底部有一个 **`debug_keys`** 选项：选中后整个界面直接显示词条 Key 本身，用来排查漏翻或文字溢出，不是给日常使用的。

### 译文质量说明

- `zh`、`zh_TW`、`en`、`ja`、`ko`、`de`、`fr`、`es`、`ru`、`pt`、`it`、`nl`、`pl`、`tr`、`id`、`vi` 共 16 种为人工逐条维护的全量译文。
- 其余 36 种采用三层合并：**官方 LocalSend 人工译文（可用 27 种，命中 52 条精确键）→ 既有 22 条核心文案 → 离线 NLLB 机翻补齐 353 条**，随后人工修正了约 140 处明显错译（例如挪威语、阿拉伯语、孟加拉语的若干条目）。
- 因此这 36 种的语言质量是「可用但非逐条精修」。看到明显别扭的句子，欢迎按第七节的流程提 PR。

## 四、回退规则

`I18nManager.get(key)` 的查找顺序是固定的四步：

1. 当前语言包里有没有这条 key；
2. 没有则用**英文**（`en`）；
3. 再没有则用**简体中文**（`zh`）；
4. 都没有才返回 key 本身（正常情况下不应该发生）。

补充说明：

- 1.7.12 新增的 4 条文案（重新发送、点选设备提示、熄屏空闲暂停服务及其说明）只补进了 **10 个基础语种**（zh / zh_TW / en / ja / ko / de / fr / es / ru / pt）。其余 42 种会按上面的规则显示英文——这是有意的取舍，避免为 4 条短句再跑一轮全量机翻。
- `debug_keys` 模式下不参与上述回退，直接显示 key。

## 五、语言包按需加载

52 种全量一次性建表要占约 1MB 堆、多花几十毫秒冷启动。1.7.11 起改为：

1. 启动时只常驻 **10 个基础包**（en / zh 作兜底，及 ja / ko / de / fr / es / ru / pt / zh_TW）；
2. 当前语言确定后，由 `I18nManager.ensureLoaded(lang)` 把该语言包构建一次（幂等、线程安全）；
3. `get()` 里还有一层兜底加载，防止静态初始化阶段先取词条。

实测（桌面 JVM 反射）：静态初始化后 10 个包；把 52 个 code 全量 `ensureLoaded` 后仍是 52 包、18,363 条；重复调用不会重复建表。

注意：懒加载省的是**运行时堆与冷启动**，不是安装包体积——字符串常量依然留在 dex 里。

## 六、常见问题

**切换语言后界面没变？**
设置里保存后 Activity 会重建；如果停留在某个二级页面，返回一次即可。`app_lang` 存在 `oldsend` 这份 SharedPreferences 中。

**为什么某些语言里混着英文？**
命中第四节第 2 条的回退规则。典型是 1.7.12 新增的 4 条文案，或某语言包尚未覆盖的长尾词条。

**为什么网页端只有 10 种语言？**
网页端字典独立于 App，写在 `assets/index.html` 里，只覆盖 10 种。若需要更多语种，得单独扩前端字典（尚未做）。

**繁体中文和简体中文是同一份吗？**
不是。`zh_TW` 是独立的 353 条繁体词条，`zh` 与 `zh_TW` 互不兜底，两者的兜底都走 `en`。

## 七、新增语言或词条的流程

### 加一条新文案

1. 在 `I18nManager` 的 10 个基础包里加 `put("your_key", "...")`；
2. 若要覆盖全部 52 种语言，再到对应的 `installFullXx()` 里补；
3. 至少保证 `en` 有值，否则会回退到中文；
4. 用 `debug_keys` 检查有没有漏翻、文字是否溢出。

### 加一门新语言

1. 写一个 `installFullXx()`，全量 353 条（可先以 `en` 包为模板复制再翻译）；
2. 把新 code 加进 `CODES` 与 `LABELS`（顺序即设置页展示顺序，`system` 恒为第一项）；
3. **必须在 `ensureLoaded()` 里登记分支**，否则该语言永远不会被装载，界面会一直显示英文；
4. 如果需要 `iw / in / tl / no` 这类系统历史代码，补进 `normalizeCode()`；
5. 校验：静态初始化后包数应为 10，全量加载后为 52（新增语言后相应 +1），每包 353 条（10 个基础语种因额外保留 4 条历史文案为 357–358 条）。

### 提交前自查

- 切换目标语言，逐页走一遍：首页、设备列表、传输页、设置、历史、关于；
- 检查长句在圆屏上是否被裁切（必要时用 0.3x～2.5x 的 UI 缩放看极限情况）；
- 确认没有出现裸 key。
