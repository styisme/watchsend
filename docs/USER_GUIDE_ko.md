# WatchSend 사용 설명서

> 워치 파일 전송 · 사용자 매뉴얼

적용 버전 1.8.0(versionCode 10800)　2026년 11월

## 1 이 설명서에 대하여

이 설명서는 WatchSend 사용자를 위해 설치, 연결, 송수신 절차와 설정 화면의 각 항목이 실제로 무엇을 하는지 설명합니다. 버튼과 메뉴 이름은 현재 표시 언어의 표기와 같습니다. 표시 언어를 바꾸었다면 같은 언어의 판을 참고하십시오.

다루는 범위는 사용법뿐이며 빌드, 패키징, 개조 절차는 포함하지 않습니다. 개발 환경과 기여 규칙, 언어 팩 유지 관리는 저장소의 CONTRIBUTING 과 docs 를 보십시오. 설명은 1.8.0 구현을 기준으로 합니다. 클라우드 빌드 환경에서는 에뮬레이터를 띄울 수 없으므로 제스처 감각은 실기에서 확인하십시오.

## 2 설치와 첫 실행

WatchSend 는 APK 로 배포되며 Android 2.3(API 10) 이상에서 동작합니다. 워치에도, 송수신용 휴대폰에도 설치할 수 있습니다. 워치에는 보통 adb 로 설치하거나 휴대폰의 워치 보조 앱으로 전송해 설치합니다. 설치 후 앱 목록에서 WatchSend 를 열면 되고 로그인이나 계정은 필요하지 않습니다.

첫 실행 시 알림과 저장소 권한을 요청합니다. 알림은 수신 파일과 전송 진행을 백그라운드에서 알리는 데, 저장소는 파일을 갤러리나 기록 폴더에 쓰는 데 씁니다. 거부해도 앱이 종료되지는 않지만 백그라운드 알림이 빠지고 일부 수신 경로가 실패할 수 있으므로 둘 다 허용하는 편이 좋습니다.

홈 화면 위쪽이 서비스 스위치이며 ‘시작’인지 ‘중지’인지, 실행 상태와 이 기기 주소를 보여 줍니다. 중지 상태에서는 다른 기기가 이 기기를 찾지 못합니다. 시작을 누르면 53317 번 포트로 HTTP 서비스를 열고 주기적인 멀티캐스트 탐색을 시작하며, 이때부터 송수신이 가능합니다.

## 3 화면과 기본 조작

홈 화면은 위에서부터 상태와 주소, 기기 목록, 그리고 보내기·수신 기록·크로스넷·설정·로그 진입점 순입니다. 목록은 두 가지로 스크롤합니다. Wear OS 3 이상에서는 용두를 돌릴 수 있고 손가락으로 위아래로 밀 수도 있습니다. 스크롤할 때 가장자리 카드가 줄고 투명해져 현재 위치를 알려 줍니다.

- 카드를 누르면 한 단계 들어갑니다. 화면 아래의 뒤로 버튼이나 시스템 뒤로로 현재 화면을 나갈 수 있습니다.
- 앱 내 스와이프 뒤로가 기본으로 켜져 있습니다. 화면 가장자리에서 옆으로 밀면 페이지가 손가락을 따라 줄고 흐려지며 이전 화면으로 돌아갑니다. 시스템 뒤로가 더 익숙하면 ‘설정 → 일반 → 앱 내 뒤로 사용’을 끄십시오. 끄면 시스템 뒤로가 원래대로 돌아오고 스와이프는 뒤로 동작을 하지 않습니다.
- 설정의 ‘화면 크기’는 0.3x 에서 2.5x 까지 앱 전체의 글자와 구성 요소 크기를 바꿉니다. 둥근 화면에서 답답하면 이것부터 조정하십시오.
- 둥근 워치는 원형 화면 최적화를 켜십시오. 아래 턱이 있는 기종(Moto 360 등)은 ‘하단 여백’도 켜야 버튼이 잘리지 않습니다.

## 4 파일 보내기

보내기는 네 단계로 순서가 고정입니다. 내용 고르기, 기기 고르기, 전송 확정, 진행 기다리기. 도중에 돌아가 선택을 바꿀 수 있고 고른 항목은 보낼 목록에 남습니다.

1. 홈에서 ‘보내기’를 누르면 종류 메뉴가 열립니다. 파일, 미디어, 앱, 폴더, 텍스트, 클립보드입니다.
2. 항목을 고릅니다. 파일과 미디어는 여러 개를 고를 수 있고, 앱과 폴더는 하나씩, 텍스트와 클립보드는 현재 내용을 그대로 씁니다.
3. 목록으로 돌아가 대상 기기를 누릅니다. 상대는 서비스를 켠 상태여야 하고 같은 네트워크에 있거나 크로스넷 설정이 끝나 있어야 합니다.
4. 진행 막대가 끝날 때까지 기다립니다. 성공하면 알림과 진동이, 실패하면 오류 코드가 나오며 ‘로그’ 화면에서 세부를 볼 수 있습니다.

텍스트는 LocalSend 텍스트 메시지로 전송되어 상대가 알림이나 대화에서 본문을 봅니다. 클립보드는 현재 내용을 하나의 텍스트로 보내는 것이며 이미지는 보내지 않습니다. 큰 파일을 보내는 동안 화면은 켜진 상태를 유지하고 끝나면 절전 논리로 돌아갑니다.

## 5 파일 받기

서비스가 켜져 있으면 같은 네트워크의 기기가 이 기기를 찾아 보낼 수 있습니다. 받기 전에 확인 화면이 떠서 보낸 사람 이름, 파일 수, 총 용량을 보여 줍니다. 받거나 거절할 수 있고, 거절하면 상대에 즉시 알려 오래 기다리게 하지 않습니다.

‘빠른 저장’은 이 확인을 건너뛸지 정하며 세 단계입니다. 매번 묻기, 모두 자동 받기, 즐겨찾기만 자동 받기. 기본은 매번 묻기이므로 처음에는 그대로 쓰고 보낸 사람을 신뢰하게 되면 자동으로 바꾸십시오.

큰 파일은 이어받기를 지원합니다. 중단 뒤 다시 보내면 이미 기록된 위치부터 이어지며 처음부터 다시 하지 않습니다. 받은 사진과 동영상은 설정에 따라 갤러리로, 나머지는 기록으로 저장되며 둘 다 설정에서 따로 끌 수 있습니다.

## 6 웹 화면과 크로스넷 전송

### 6.1 웹 화면

서비스를 켠 뒤 같은 LAN 의 컴퓨터 브라우저에서 홈에 보이는 주소(예 http://192.168.1.100:53317)를 열면 최소한의 페이지가 나옵니다. 파일을 끌어다 보낼 수 있고 여러 파일의 진행을 볼 수 있으며 워치와 클립보드 텍스트를 주고받을 수 있습니다. 홈의 주소는 눌러 복사할 수 있고 ‘웹 URL’을 열면 QR 코드가 나와 휴대폰으로 찍을 수 있습니다.

웹 화면의 내장 언어는 브라우저를 따르며 10가지입니다. 중국어 간체, 중국어 번체, 영어, 일본어, 한국어, 독일어, 프랑스어, 스페인어, 러시아어, 포르투갈어. 앱 본체는 52개 언어이며 해당 언어가 없으면 영어로 되돌아갑니다.

### 6.2 크로스넷 전송

같은 LAN 밖에서는 두 가지 길이 있습니다. 비밀번호 방식은 한쪽이 6자리 일회용 코드를 만들고 다른 쪽이 크로스넷 화면에 입력하면 연결되며 공인 IP 가 필요 없습니다. 직접 연결 방식은 FRP, Ngrok, ZeroTier 등으로 포트를 공개한 뒤 수동 입력란에 IP:53317 을 넣습니다. 속도는 통과 경로에 따릅니다.

크로스넷은 제3자 설비와 사용자의 회선에 의존하므로 안정성을 이 앱이 보장하지 않습니다. 연결이 되지 않으면 먼저 로그 화면에서 상대 주소와 포트에 도달되는지, 다음으로 통과 서비스가 켜져 있는지 확인하십시오.

## 7 기록

‘수신 기록’은 주고받은 파일과 텍스트를 최신순으로 보여 주며 압축 파일에는 표시가 붙습니다. 길게 누르면 동작 메뉴가, 누르면 세부나 파일 자체가 열립니다.

- 다시 보내기: 그 기록의 파일을 보낼 목록으로 되돌립니다. 목록으로 돌아가 기기를 누르면 다시 보낼 수 있고 폴더를 다시 찾을 필요가 없습니다.
- 공유: 시스템 공유로 파일을 다른 앱에 넘깁니다.
- 압축 풀기: 압축 파일에만 가능하며 내장 순수 Java 엔진을 쓰고 경로 이탈 방어가 있어 대상 폴더 밖에 쓰지 않습니다.
- 삭제: 그 기록을 지웁니다. 갤러리에 저장된 파일은 영향을 받지 않습니다.

## 9 자주 묻는 문제

**표 2　증상과 대처**

| 증상 | 대처 |
| --- | --- |
| 목록이 ‘기기 없음, 스캔을 누르세요’에 머묾 | 상대 서비스가 켜져 있고 같은 Wi-Fi 인지 확인. 공유기의 AP 격리를 끔. 스캔을 다시 시도. 그래도 없으면 IP 를 직접 입력 |
| 상대가 보낼 때 모두 400 오류 | 프로토콜 항목이나 HTTPS 상태가 어긋난 경우가 많음. 양쪽에서 HTTPS 를 끄거나 같은 버전으로 맞춘 뒤 다시 시도하고 로그 화면에서 상태 코드 확인 |
| 브라우저에서 웹 화면이 열리지 않음 | 서비스 실행, 포트가 다른 앱에 잡히지 않았는지, 컴퓨터와 워치가 같은 서브넷인지 확인. 기기 간 통신을 기본 차단하는 공유기도 있음 |
| 뒤로 키가 반응하지 않거나 안내만 뜸 | 앱 내 뒤로가 켜져 있음. 끄면 시스템 뒤로가 정상 동작 |
| 글자나 버튼이 둥근 모서리에 잘림 | 원형 화면 최적화를 켜고 필요하면 하단 여백도 켜며 화면 크기를 한 단계 줄임 |
| 화면이 꺼진 뒤 잠시 후 받지 못함 | 화면 꺼짐 시 서비스 일시정지가 켜져 있는지(기본 끔), 시스템이 WatchSend 를 배터리 최적화하는지 확인 |
| 전송 중 배터리가 빨리 줄어듦 | 저성능 모드를 켬. 배터리 15% 미만이고 충전 중이 아니면 앱이 512KB/s 로 자동 제한 |

## 10 보안, 절전, 알려진 제한

- 기본은 평문 HTTP 이며 신뢰할 수 있는 LAN 에만 적합합니다. 암호화가 필요하면 HTTPS 를 켜고 상대 인증서 지문을 확인하십시오.
- PIN 기본값은 0000 입니다. 자신의 네 자리로 바꾸십시오. 크로스넷은 6자리 일회용 코드를 쓰며 사용 후 만료됩니다.
- 위험 확장자 exe, bat, cmd, vbs, sh 는 기본으로 차단합니다. 화이트리스트와 블랙리스트는 기기 길게 누르기 메뉴에서 관리합니다.
- 절전은 세 층입니다. 저성능 모드는 대부분의 애니메이션을 끄고 2MB/s 로 제한합니다. 배터리 15% 미만이며 충전 중이 아니면 512KB/s, 화면 꺼짐 3분이면 서비스를 멈춥니다(기본 끔, 전송 중이면 연장).
- 알려진 제한: 크로스넷은 제3자 설비에 의존해 안정성을 보장하지 않습니다. 무음 설치는 ROM 제한을 받습니다. 오래된 기기에는 진동 모터나 용두가 없을 수 있습니다. 압축 풀기와 제스처는 소형 실기에서만 확인했습니다.
- 이 프로젝트는 MIT 로 공개되며 AI 지원으로 생성한 뒤 사람이 검토하고 실기에서 조정했습니다. 현 상태로 제공하며 적합성을 보증하지 않습니다.
